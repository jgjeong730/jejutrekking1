02

미리 알아두면 좋은 말들

아래 여정 로그에서 계속 나오는 용어예요. 처음 봐도 되도록 쉽게 풀어썼어요.

React / Vite

화면을 그리는 도구(React)와, 그걸 빠르게 개발·빌드해주는 도구(Vite). 둘 다 그냥 "코드를 화면으로 바꿔주는 엔진"이라고 생각하면 돼요.

Git commit / push

수정한 코드에 "이만큼 저장!"이라고 도장 찍는 것(commit), 그걸 온라인 저장소에 올리는 것(push). 되돌리기 가능한 저장 지점이 생겨요.

빌드 / 배포(deploy)

내 컴퓨터에서만 보이던 코드를 "실제로 작동하는 완성품"으로 만드는 게 빌드, 그걸 인터넷에 올려 누구나 접속하게 하는 게 배포예요.

localStorage

웹사이트가 "그 브라우저 안에만" 저장해두는 메모장. 다른 기기나 다른 사람은 절대 못 봐요 — 이게 이번 프로젝트의 큰 반전 포인트였어요 (7장 참고).

Supabase

클라우드에 있는 공용 데이터베이스. localStorage와 달리 모두가 같은 데이터를 보게 해줘요 — "링크 공유하면 진행상황이 보이나?"의 답이 여기 있어요.

API 키 (공개키 vs 비밀키)

공개키(anon key)는 브라우저에 그대로 노출돼도 괜찮게 설계된 키, 비밀키(service role)는 서버만 알아야 하는 관리자 키. 절대 섞어 쓰면 안 돼요.

권한 모드 (Auto / Plan)

Auto는 코드 수정·명령 실행을 거의 자동으로 진행하는 모드, Plan은 먼저 조사만 하고 계획을 승인받은 다음에 실행하는 모드. 반복 작업엔 Auto, 되돌리기 까다로운 큰 결정엔 Plan이 어울려요 (11장 참고).

05

도구 이해하기 — Cursor·터미널, Git·GitHub

작업 중 자주 헷갈리는 네 가지 도구의 관계를 따로 정리했어요. 코딩을 모르는 분께 설명할 때도 결론부터 먼저 말하면 훨씬 잘 통해요.

1) Cursor vs 터미널

결론 — Cursor는 "큰 작업실(IDE)", 터미널은 "그 작업실 안의 명령어 입력 창"이에요. 둘은 대등한 비교 대상이 아니라 포함 관계예요.

Cursor (IDE, 프로그램 전체) ├─ 파일 탐색기 (좌측 폴더 목록) ├─ 코드 에디터 (색깔 강조, 자동완성) ├─ 디버거 └─ 터미널 패널 ← 이 안에서 명령어 입력 └─ PowerShell (Windows 기본 명령어 프로그램) └─ claude, node, npm, git 같은 명령어 실행
구분Cursor터미널
정체IDE(통합개발환경) — 코딩용 종합 프로그램IDE 안의 기능 하나 — 명령어 입력 창
역할코드 보기·수정·파일관리·실행 전체를 담당텍스트 명령으로 컴퓨터 조작
예시좌측 파일트리, 상단 메뉴바(File/Edit/View)claude doctor, node --version 입력하던 검은 창
독립 실행가능 (자체 프로그램)Windows에 원래 내장 — Cursor 안에서도, 시작메뉴에서도 열림

헷갈렸던 포인트

헷갈렸던 것정답
"Cursor가 터미널 아닌가?"아니오 — Cursor는 IDE, 터미널은 그 안의 패널
"VS Code랑 Cursor 구분이 안 됨"Cursor는 VS Code를 포크해서 만든 별도 프로그램 — UI가 거의 같아서 헷갈림 (좌측 상단 로고, 하단 상태바의 "Cursor" 텍스트로 구분)
"시작메뉴로 연 PowerShell이 이상한 위치(system32)에서 시작됨"정상 — Cursor 안에서 열면 자동으로 프로젝트 폴더에서 시작, 시작메뉴로 직접 열면 cd 명령으로 위치 이동 필요

2) Git vs GitHub

결론 — Git은 "코드 변경 이력을 저장하는 개인 다이어리", GitHub는 "그 다이어리를 인터넷에 올려 공유하는 클라우드 저장소"예요.

항목GitGitHub
정체프로그램 (버전 관리 도구)웹사이트/서비스 (Git 파일을 저장하는 클라우드)
위치내 컴퓨터 안에 설치인터넷 상의 서버
비유문서 작업할 때 "저장" 버튼저장한 문서를 구글드라이브에 올리는 것
관계GitHub는 Git을 사용하는 여러 서비스 중 하나 (다른 예: GitLab, Bitbucket)

Git은 코드가 바뀔 때마다 "스냅샷"을 찍어 기록하는 도구예요.

[월요일] 코드 작성 → 커밋(저장) → "지출 입력 기능 추가" [화요일] 코드 수정 → 커밋(저장) → "버그 수정" [수요일] 코드 수정 → 커밋(저장) → "디자인 개선"

이렇게 저장해두면 언제 뭘 고쳤는지 역사가 남고, 실수했을 때 예전 버전으로 되돌릴 수 있고, 여러 사람이 같은 파일을 동시에 작업해도 충돌 없이 합칠 수 있어요.

용어의미비유
커밋 (Commit)지금 상태를 로컬에 저장문서 "저장" 버튼
푸시 (Push)저장한 걸 GitHub로 업로드클라우드에 올리기
풀 (Pull)GitHub에 있는 최신 버전을 내려받기클라우드에서 최신 파일 받아오기

GitHub는 Git으로 기록한 코드 역사를 인터넷에 올려 저장·공유하는 웹사이트예요.

기능설명
백업내 컴퓨터가 고장 나도 코드는 GitHub에 안전하게 보관됨
공유/협업다른 사람과 같은 프로젝트를 함께 작업 가능
GitHub Pages코드를 실제 웹사이트로 배포 가능 (예: jgjeong730.github.io)
이력 확인웹 화면에서 누가 언제 뭘 고쳤는지 시각적으로 확인

실제 겪은 흐름으로 정리하면

1. Cursor에서 코드 수정 (Claude Code가 파일 고침) ↓ 2. Git이 로컬에 "커밋" — 변경사항 기록 ↓ 3. GitHub로 "푸시" — 인터넷 저장소로 업로드 ↓ 4. GitHub Pages가 자동으로 "배포" — 실제 웹사이트로 반영 ↓ 5. 실제 웹사이트에서 확인 가능
Committed → Pushed to main → 배포 완료 → 실제 사이트에서 확인 — 이게 매번 반복되는 배포 로그의 순서예요.

비유로 최종 정리

개념비유
Git문서 작업 이력을 남기는 "버전 관리 수첩"
커밋수첩에 "오늘 이렇게 고쳤음" 한 페이지 적기
GitHub그 수첩을 클라우드(구글드라이브)에 올려두는 곳
푸시수첩 내용을 클라우드에 업로드
저장소 (Repository)프로젝트별로 만든 "폴더" (예: jejutrekking1)

전체 작업 도구 최종 정리 (지금까지 배운 모든 개념 통합)

레이어이름역할

② 명령어 창터미널 패널 (PowerShell)Cursor 안에서 명령어 입력하는 곳
③ AI 에이전트Claude Code CLI터미널 안에서 claude 명령으로 실행되는 코딩 AI
④ 실행 엔진Node.js / npm자바스크립트 코드를 실행하는 도구
⑤ 버전 관리Git코드 변경 이력을 로컬에 기록
⑥ 클라우드 저장소GitHubGit 기록을 인터넷에 올려 백업·배포

실전 사용 흐름 — 지금 JG가 매번 하는 패턴이에요.

1. Cursor 실행 → 프로젝트 폴더 열기 (예: jeju_family) 2. 터미널 패널 열기 (자동으로 해당 폴더 위치에서 시작) 3. 터미널에 claude 입력 → Claude Code 에이전트 실행 4. 자연어로 작업 요청 (예: "지도에 경로선 그려줘") 5. Claude가 파일 수정 → Git 커밋 → GitHub 푸시 → 배포까지 자동 진행 6. 실제 웹사이트(jgjeong730.github.io)에서 결과 확인

한 줄 결론 — Cursor는 집 전체, 터미널은 그 집 안의 전화기(명령 전달 창구)예요. 서로 경쟁 관계가 아니라, 터미널은 Cursor의 여러 도구 중 하나일 뿐이에요.

지인에게 이 문서를 보여주신다면 이렇게 정리해보셔도 좋을 것 같아요:

"코딩"은 처음부터 정답을 아는 게 아니라, 하고 싶은 걸 말로 표현하고 → 결과를 보고 → 다시 다듬는 대화의 연속이에요. 이 문서에 나온 50번 남짓한 대화 하나하나가, 지금 인터넷에 떠 있는 이 앱을 만든 전부예요.
